# الحَكَم الذكي | Football Laws RAG

مساعد عربي تجريبي لشرح قوانين كرة القدم بالاستناد إلى وثائق رسمية وإظهار الأدلة والمراجع.

## حالة المشروع

تم تنزيل وفحص المصدر الأساسي: قوانين اللعبة 2026/27 بالعربية (236 صفحة، والنص قابل للاستخراج). يحتوي سجل الجمع على 33 مصدرًا رسميًا مستخرج النص (29 HTML و4 PDF) دون حالات فشل. بعد احتساب نسختي نشرة تغييرات القوانين العربية والإنجليزية كوثيقة واحدة، يبلغ عدد هويات الوثائق 32. فحص الاستخراج وجد 236/236 صفحة قابلة لاستخراج النص، لكن 113 صفحة تحتاج مراجعة بصرية. اطلع على تقارير تدقيق corpus والاستخراج وبناء المقاطع قبل إنشاء الفهرس. لم تُقَس Recall@5 أو RAGAS بعد، ولم تُجرَ اختبارات المستخدمين. تدقيق النص لا يغني عن المراجعة البصرية للصفحات المعلّمة.

راجع [`PROJECT_CHECKLIST.md`](PROJECT_CHECKLIST.md) لمتابعة كل متطلبات المساق وعناصر التسليم الخمسة. لا تُعدّ أي نتيجة أو متطلب منجزًا قبل التحقق الفعلي منه.

## الملفات

- `domain.md`: تعريف المجال والنطاق والقيود.
- `data/sources_manifest.csv`: سجل المصادر وحالة التحقق والتنزيل.
- `data/raw/`: لقطات المصدر الخام مستثناة من Git لتقليل الحجم؛ يعيد `scripts/collect_sources.py` تنزيل المصادر من روابط السجل.
- `data/extracted/laws_pages.jsonl`: استخراج أولي صفحة بصفحة مع رقم الصفحة.
- `data/eval/extraction_qa.json`: فحص قابلية استخراج النص وصفحات المراجعة البصرية.
- `data/eval/corpus_audit.md` و`corpus_audit.json`: منهجية عد الوثائق ونتائج التكرار والتداخل.
- `data/eval/pdf_extraction_review.md`: مقارنة بصرية لعينة من صفحات الاستخراج مع بديل PyPDF.
- `data/eval/pdf_manual_review.json`: سجل مراجعة بصرية للصفحات التي فُحصت ونطاق ما تم التحقق منه.
- `data/eval/golden_questions_draft.json`: 30 مسودة سؤال مرتبطة بمصادر ومواد وصفحات؛ ليست بعد مجموعة التقييم الذهبية النهائية، ومعرّفات المقاطع الذهبية لم تُثبت.
- `data/eval/source_candidates.md`: مصادر IFAB الرسمية المرشحة وتحققها الحالي.
- `scripts/collect_sources.py`: أداة جمع الوثائق الرسمية من الروابط الموثقة، مع سجل نجاح/فشل وبصمات SHA-256.
- `scripts/audit_corpus.py`: يعيد إنتاج تقرير تدقيق corpus دون استدعاء API.
- `scripts/build_chunks.py`: يبني مقاطع قابلة للاستشهاد ويحفظ بيانات المصدر والصفحة.
- `scripts/retrieve_bm25.py`: خط أساس محلي للبحث اللفظي BM25 بلا API أو مكتبات إضافية؛ يستبعد المقاطع المعلّمة للمراجعة افتراضيًا.
- `data/eval/chunk_build_report.json`: إحصاءات بناء المقاطع الحالية؛ ملف المقاطع الناتج مستثنى من Git ويعاد توليده بالسكربت.
- `data/eval/source_collection_report.json`: تقرير الجمع والتحقق الحالي للمصادر.
- `architecture.md`: تصميم مبدئي وقرارات تقنية لم تُحسم بعد.
- `API_KEY_GUIDE.md`: شرح المفتاح السري، حفظه بأمان، وخطة الاستخدام ضمن الرصيد.
- `.gitignore`: يمنع رفع المفاتيح والبيئة الافتراضية وفهارس المتجهات؛ ملفات corpus النصية وسجل المصادر تبقى ضمن المشروع لمراجعتها وإعادة بناء الفهرس.
- `scripts/extract_pdf.py`: أداة إعادة الاستخراج وإنتاج تقرير الصفحات التي تحتاج مراجعة.
- `data/eval/`: مكان ملفات أسئلة التقييم والتقارير لاحقًا.

## الخطوة التالية

بُني خط أولي لتقسيم 33 سجل مصدر إلى 597 مقطعًا يحفظ مراجع المصدر والصفحة؛ الوسيط 325 كلمة والحد الأعلى 360 كلمة مع تداخل 55 كلمة. هذه قيم أساس للتجربة وليست قرارًا نهائيًا قبل اختبار الاسترجاع. بعد مراجعة الصفحات 59 و60 و91 و101 بصريًا للمحتوى المحدد في سجل المراجعة، بقيت 57 مقطعًا معلّمة لمراجعة المصدر، وصفحة PDF رقم 42 بلا نص مستخرج. أضيف خط أساس BM25 للتجارب المحلية؛ لم يكتمل بعد البحث الهجين أو إعادة الترتيب ولم يُحسب Recall@5 الرسمي. الخطوة التالية اعتماد تسميات المقاطع للأسئلة، ثم مقارنة BM25 بتضمين متعدد اللغات وإعادة ترتيب مرشحين. راجع `data/eval/chunk_build_report.json` للتفاصيل و`API_KEY_GUIDE.md` قبل أي استدعاءات مدفوعة.

## تشغيل خط الأساس المحلي

من مجلد المشروع بعد توفر ملفات الاستخراج:

```bash
python scripts/build_chunks.py
python scripts/retrieve_bm25.py "ما الشرط الأساسي لاحتساب الهدف؟" --top-k 5
```

هذا بحث لفظي تجريبي؛ لا يولّد إجابات ولا يمثل النظام الهجين النهائي.
